# 字幕节奏修复（SRT Rhythm Fix）

在浏览器内修复 SRT 字幕的**断句**与**毫秒时间边界**：保持文字内容与顺序不变、保持选区首条开始时间与末条结束时间不变，在「每秒字符数 / 单行字数 / 最小提示间隔」三组限制下，求**边界总移动量最小**的可行方案。支持按条**锁定锚点**（文字归属 / 开始时间 / 结束时间），求解器在严格保持全部锁定项的前提下联合调整其余断句与边界；无解时指出互相冲突的锚点及最小所需时长/间隔。所有数据仅保存在浏览器本地，不上传任何服务器。

技术栈：**React 18 + TypeScript + Vite**，纯前端、无后端。

## 一键启动

### 方式一：Docker Compose（推荐，生产构建）

```bash
docker compose up --build -d
```

然后打开：

- **地址**：http://localhost:**8080**
- 端口可改：`PORT=9000 docker compose up --build -d`

停止：`docker compose down`

### 方式二：Docker Compose（开发模式，带热更新）

```bash
docker compose -f docker-compose.dev.yml up
```

然后打开：

- **地址**：http://localhost:**5173**（Vite dev server）
- 端口可改：`DEV_PORT=3000 docker compose -f docker-compose.dev.yml up`

### 方式三：本地 Node（需 Node.js 20+）

```bash
npm install
npm run dev        # 开发：http://localhost:5173
npm run build && npm run preview   # 生产预览：http://localhost:4173
```

## 使用步骤

1. **导入 SRT**：选择本地 `.srt` 文件（兼容 BOM / CRLF / 逗号或点毫秒），或点击「载入示例」。
2. **选取字幕**：在列表中点击，选择**至多 30 条连续字幕**（再次点击端部条目可收缩选区）。
3. **锁定锚点（可选）**：每条字幕右侧有三个开关，可分别锁定——
   - **🔒文**：锁定该条的**文字归属**，求解时文字不进不出（相邻切点固定），原始换行逐字保留，且该条不再受 2 行折行限制；
   - **🔒始 / 🔒终**：锁定该条的**开始 / 结束时间**，该边界毫秒不动；
   - 选区首条开始、末条结束始终隐式锁定（按钮显示为灰色 🔒）。
   - 锁定随 `localStorage` 记住；**修改选区或参数后，仍然有效的锁定会自动保留**，也可随时点「解除全部锁定」。
4. **设置参数**：
   - **每秒字符数（CPS）**：每条字幕时长 ≥ `1000 × 字数 ÷ CPS`（节奏下限，默认 17）；
   - **单行字数**：词感知折行后的每行最大字符数（中日韩文字可逐字断行，拉丁词不拆词，默认 18）；
   - **最小提示间隔**：相邻两条字幕之间的最小间隔毫秒数（默认 120ms）；
   - 每条字幕固定最多 2 行（标准字幕规范；文字锁定条除外）。
5. **求解与比对**：点击「求最小移动方案」，左右并排展示**原稿**与**结果**——
   - 黄色底纹：跨条移动的文字；
   - 蓝色标签：该开始/结束边界移动的毫秒数；
   - 紫色 🔒 标记与紫框：**锁定项**（原稿列与结果列均会标明，锁定条文字不打黄、锁定边界显示 🔒 而非移动量）；
   - 顶部汇总：时间边界总移动量、文字移动量、移动字符数。
6. **确认导出**：点击「确认并导出 fixed.srt」下载完整 SRT（选区替换为修复结果、选区外原样保留、序号重排）。导出前会逐项校验：**锁定的文字逐字一致、锁定的开始/结束时间逐毫秒一致**，校验不通过会拒绝导出。

### 锚点冲突时的提示

若锁定导致无解，结果区会以【锚点冲突】列出**互相冲突的具体锚点对**及其时间，例如：

- `第 1 条结束锚点（00:00:01,000）与第 2 条开始锚点（00:00:01,100）互相冲突：两者间隔仅 100 ms，但相邻字幕间至少需要 500 ms 的提示间隔（1 × 500 ms），还差 400 ms。`
- `第 1 条开始锚点（…）与第 3 条结束锚点（…）互相冲突：两锚点之间仅 1180 ms，但第 1–2 条至少需要 4000 ms 展示时长…还差 2820 ms。`
- 文字锚点把若干条夹在固定切点之间时，会给出该区间字数、容量上限与**至少多出的字数**。

按提示解除其中一个锚点（或放宽 CPS / 间隔 / 单行字数）后重新求解即可恢复可解。

## 求解原理（摘要）

- **时间优化（精确全局最优）**：给定断句后，所有边界约束可变换为一条非减变量链，目标 `Σ|新边界 − 原边界|` 是标准 **L1 保序回归（Isotonic Regression）**，用 **PAVA（Pool Adjacent Violators）+ 加权中位数**精确求解；选区首/末边界及所有时间锚点用极大权重钉死，钉死点若被合并即判定该锚点配置不可行。
- **断句优化（该时间方案下精确最优）**：在分层 DAG 上做密集数组 DP，词典序最小化 `(时长缺口, 文字移动量)`，段合法性（非空、2 行折行、行长）带缓存；文字锚点把切点钉在原始位置，DP 的枚举区间由相邻固定切点推出硬界，锁定段免折行检查。
- **联合优化（非凸组合问题）**：以 3 组结构化切点（均匀 / 按原字数 / 按原时长）+ 上百组随机合法切点为起点交替迭代到不动点，再做模拟退火（单/双切点扰动，只扰动非固定切点）与确定性双邻域精修（单/双切点 ±3 直接评估原始时间目标），取其中移动量最小的方案。两个子问题均为精确解，联合层为高质量启发式（固定随机种子、结果可复现；30 条规模约 3 秒）。
- **锚点冲突预检**：时间锚点把节点链划分为若干区域，逐区核算最小展示时长（文字锁定条字数固定；自由块用「集中装填」给严格下界）与最小间隔，给出冲突锚点对、实测跨度、所需最小时长/间隔及差额；文字锚点则按固定切点切出的自由块逐块核算容量与超长拉丁词。预检通过但搜索意外失败时，再以确定性断句 DP 做一次兜底求解与按实际切点的缺口报告。
- **验证**：`npm test` 包含 1000+ 项断言，其中时间优化器在 60 个随机案例上与整数坐标暴力 DP 完全一致；小规模（≤4 条）联合求解与“枚举全部断句 × 每案最优时间”的全局最优逐一对照；锚点部分覆盖可行锁定不变量、相邻时间锚点间隔冲突、锚点间时长冲突、文字锚点容量冲突、解除锁定后恢复可解，以及 30 组随机锁定的属性测试。

## 配置一览

| 配置 | 默认值 | 位置 / 方式 |
| --- | --- | --- |
| 生产端口 | `8080` | `docker compose` 环境变量 `PORT` |
| 开发端口 | `5173` | `docker-compose.dev.yml` 环境变量 `DEV_PORT`，或 `vite.config.ts` |
| CPS 上限 | 17 | 页面参数区 |
| 单行字数 | 18 | 页面参数区 |
| 最小间隔 | 120 ms | 页面参数区 |
| 选区条数上限 | 30 | 页面逻辑（`MAX_SELECTION`） |
| 每屏行数上限 | 2 | 求解器常量（`MAX_LINES`；文字锁定条除外） |
| 锚点锁定 | 无（手动开启） | 选区列表每行的「文 / 始 / 终」开关 |

参数与锚点锁定都会随浏览器 `localStorage` 记住（导入新文件会清空锁定）；导入的 SRT 原文同样仅存于 `localStorage`，可在页面上「清空」。
